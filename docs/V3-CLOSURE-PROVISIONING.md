Activation remains **BLOCKED**. These are review/provisioning contracts, not commands to enable a writer. Keep the original activation checklist and V2 migration plan as the ordered authority.

## PostgreSQL

Use PostgreSQL 18 UTF8 with a DNS identity present in the certificate SAN, a separately pinned CA, `hostssl` SCRAM or client certificate authentication, restricted CONNECT privileges and no public schema CREATE. `ProductionPostgreSQLAdapter` accepts exactly `host`, `port`, `dbname`, `user`, `schema`, `sslrootcert`, `sslrootcert_sha256`, `application_name`; supply the password from separately managed custody. No URL, alternate SSL mode, hostaddr or service DSN is accepted. TLS uses `verify-full`, including hostname verification ([PostgreSQL documentation](https://www.postgresql.org/docs/18/libpq-ssl.html)). No production connection executes in this PR.

`provisioning_sql()` generates the review artifact: separate NOLOGIN schema owner and LOGIN writer, no superuser/CREATEDB/CREATEROLE/REPLICATION/BYPASSRLS, SELECT/INSERT on the five ledger tables, UPDATE only on head/attempts, no DELETE/TRUNCATE/TRIGGER/REFERENCES or ownership. Audit events, consumed identities and historical views are append-only for the writer. Install this DDL through a separately authorized DBA operation; runtime ledger initialization never supplies DDL. Revoke unused database/public grants and forbid membership in privileged roles. Provision fsync, full_page_writes, synchronous replication policy, backups, WAL retention and external failover drills; `synchronous_commit=on` alone cannot prove those operational properties.

Seed a genuinely empty schema only after fresh independent verification of exact storage commit, complete inventory, absent Git stable publication and independent HTTPS absence, plus exclusive writer control. `initialize_empty_rehearsal` exercises this typed contract only through the loopback test factory. It rejects any nonempty table, and normal constructors still reject a missing historical head. Actual protected import/bootstrap consumption and real checkpoint seeding need the activation review. Never interpret a 404 by itself as authenticated absence.

## Independent checkpoint and observer

Operate checkpoint storage/signing outside the DB/runner backup and administrator failure domains. Use a distinct canonical RSA public root, append-only storage with CAS, verified HTTPS, bounded request bodies, a trusted UTC clock and externally documented restore policy. `AuthorityClient` challenges every read with a random nonce; replies bind name/value/nonce and a 30-second lifetime. Signed updates bind the observed previous value. Checkpoint sequence cannot decrease or change hash at the same sequence.

`CheckpointedLedger` fetches the independent tip on every inspect/mutation and checks signed audit ancestry. Before DB commit it durably reserves the exact next signed audit checkpoint independently; after commit it acknowledges that target. Lost responses reconcile by checking the reservation and actual signed DB state. An absent reserved target blocks writes and requires a fresh separately signed `restore-observation` proving noncommit and fenced writers; a local database assertion cannot clear it. DB-behind restores and unreserved DB-ahead history fail closed. This is a recovery protocol, not a cross-service atomic transaction. Do not return an externally accepted receipt before independent acknowledgement. The local HTTP service and SQLite fsync tests do not establish independent production operation or HA.

History genesis records bind the full V3 candidate identity, group, publication run, availability evidence digest and the observer's current UTC timestamp. They are immutable. Repeated observation does not reset dwell, and old legacy timestamps are never imported. The observer must independently verify real beta HTTPS bytes, signed metadata, snapshot membership, source identity and availability logs before signing an update. Run identity and authenticated source attestations remain separate requirements.
