## Composition and trust

`build-candidate-snapshot.yml` retains its protected `repo-production-signing`
environment, signing-run API checks, exact accepted/signed artefact downloads,
and metadata-only signing secrets. When `parent_snapshot` is supplied it checks
out Pages storage read-only and passes `--base-snapshot` to the normal V2 builder.
Only new component signing-run artefacts are required. Old signing-run retention
is irrelevant: inherited packages come from the signed immutable snapshot.

The parent is checked for symlinks, manifest/repodata signatures, trusted role
fingerprints, exact RPM inventory, all physical noarch copies, RPM headers and
production RPM signatures. Replacements must cover a complete registry group,
keep every old package/architecture identity and strictly increase RPM EVR.
Duplicate groups, orphan SRPMs, missing source closure and composed file
conflicts fail before a candidate is committed. Every inherited copy is checked
against the original signed SHA-256. New binary noarch packages go into both
x86_64 and aarch64; SRPMs go into source. Parent data is never modified.

The existing metadata key signs new repodata, snapshot manifest and build
evidence. Optional `inherited_snapshot` evidence binds the parent manifest digest
and exact retained/replaced package records. Existing candidate verification,
catalog generation, publication, rollback, selective Stable and Pages writer/CAS
workflows remain in place. The catalog is generated by the existing publication
signer; this PR adds no Ro-Store application or Ro-Control packages.

Widgets is registered as `critical-desktop`, noarch, SRPM required, no Fedora
override. Its required evidence includes `plasma-integration` and `login-session`
in addition to dependency solve, install, upgrade, conflicts, rpmlint and smoke.
Those graphical integration checks need real Plasma session evidence before a
future Stable promotion; an RPM install alone does not demonstrate them.

## Validation boundaries

`tests/test_v2_candidate.py` exercises the exact 23-entry baseline inventory,
21-entry retention, 25/27 arithmetic, missing SRPM, incorrect noarch, architecture
loss, wrong role/parent, duplicate group and downgrade/same-version rejection.
`tests/candidate-expansion-e2e.py` generates temporary Fedora RPMs and keys,
constructs signed 23/25/27-entry snapshots, removes old signing inputs, checks
byte preservation, real RPM/repodata signatures and runs real Fedora 44 DNF5
clean/upgrade transactions. Its future Widgets version `99.0` is explicitly a
synthetic fixture, never an accepted producer release. The signing transport
handoff is mocked in this composer test; existing signing tests cover that
boundary. The normal acceptance, rollback, Pages CAS and PR #83 regressions
remain mandatory.
